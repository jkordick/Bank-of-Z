# Business rules

## XFRFUN

Scope: the transfer back-end, its copybooks and its directly linked error recorder. The generated digest reports a successful parse and 40 decisions (`docs/modernization/00-source-of-truth/programs/XFRFUN.md:12`). **This is not complete tooling verification:** the source has an additional rollback-response decision absent from the digest; see XFRFUN-Q01 in `open-questions.md`. Unresolved paths below are observations, not assertions about intended behavior.

Amounts and returned balances are signed fixed-point `PIC S9(10)V99`, not floating point (`src/base/cics/copy/XFRFUN.cpy:11`). Examples assume valid numeric input, representable amounts and successful SQL/rollback operations unless stated otherwise.

- **XFRFUN-R01 - Both accounts use the configured local sort code, regardless of supplied sort codes.** Before the amount decision, the program overwrites `COMM-FSCODE` and `COMM-TSCODE` with `SORTCODE`, whose checked-in value is `987654`. Subsequent account lookups use these overwritten keys. Example: `COMM-FSCODE=111111`, `COMM-TSCODE=222222`, `COMM-FACCNO=00000001`, `COMM-TACCNO=00000002` -> lookups at `987654/00000001` and `987654/00000002`, with both COMMAREA sort codes now `987654`. Evidence: `src/base/cics/cobol/XFRFUN.cbl:281`, `src/base/cics/cobol/XFRFUN.cbl:289`, `src/base/cics/cobol/XFRFUN.cbl:924`, `src/base/cics/cobol/XFRFUN.cbl:1051`; literal: `src/base/cics/copy/SORTCODE.cpy:7`.

- **XFRFUN-R02 - Zero and negative transfers are rejected before account processing.** At `COMM-AMT <= ZERO`, return `COMM-SUCCESS='N'`, `COMM-FAIL-CODE='4'` through the CICS return routine; no account or history SQL is reached. Example: `COMM-AMT=0.00` or `-0.01` -> `N/4`; `0.01` passes this gate but is not guaranteed to succeed. Evidence: `src/base/cics/cobol/XFRFUN.cbl:289`, `src/base/cics/cobol/XFRFUN.cbl:296`, `src/base/cics/cobol/XFRFUN.cbl:1873`.

- **XFRFUN-R03 - A positive transfer to the same effective account abends rather than returning an ordinary rejection.** Equal account numbers and equal sort codes cause an error-recording LINK followed by `ABEND 'SAME' NODUMP CANCEL`. Because R01 runs first, matching account numbers suffice here even if the caller supplied different sort codes. Example: `COMM-AMT=1.00`, `COMM-FACCNO=COMM-TACCNO=00000001`, originally different sort codes -> `COMM-SUCCESS` is set to `N`, then `SAME`; there is no normal failure-code return. For `COMM-AMT=0.00`, R02 takes precedence. Evidence: `src/base/cics/cobol/XFRFUN.cbl:289`, `src/base/cics/cobol/XFRFUN.cbl:311`, `src/base/cics/cobol/XFRFUN.cbl:316`, `src/base/cics/cobol/XFRFUN.cbl:364`, `src/base/cics/cobol/XFRFUN.cbl:370`.

- **XFRFUN-R04 - Process the lower account number first and attempt the second account only after the first reports success.** If `COMM-FACCNO < COMM-TACCNO`, debit FROM then credit TO; otherwise credit TO then debit FROM. A second operation reporting `COMM-SUCCESS='N'` enters the failure handling rather than history writing. Example: FROM `00000020`, TO `00000010`, `COMM-AMT=5.00` -> credit `00000010` first; reverse the numbers -> debit `00000010` first. The equality arm exists syntactically, but R01/R03 intercept equal effective keys; its independent runtime use is not assumed. Evidence: `src/base/cics/cobol/XFRFUN.cbl:378`, `src/base/cics/cobol/XFRFUN.cbl:394`, `src/base/cics/cobol/XFRFUN.cbl:404`, `src/base/cics/cobol/XFRFUN.cbl:606`, `src/base/cics/cobol/XFRFUN.cbl:615`.

- **XFRFUN-R05 - Debit and credit both balances by exactly the transfer amount, without an overdraft gate.** After a successful FROM read, subtract `COMM-AMT` from available and actual balances; after a successful TO read, add it to both. Successful updates copy the results into `COMM-FAVBAL`, `COMM-FACTBAL`, `COMM-TAVBAL`, `COMM-TACTBAL`. There is no intervening comparison to the retrieved overdraft limit. Example: `COMM-AMT=25.00`, FROM available/actual `10.00/15.00`, TO `100.00/110.00` -> returned balances `-15.00/-10.00` and `125.00/135.00`, provided the remaining operations succeed. Overall `COMM-SUCCESS='Y'` is assigned after history writing; `COMM-FAIL-CODE` is not cleared on that path, so it is not a success indicator. Evidence: decisions `src/base/cics/cobol/XFRFUN.cbl:964`, `src/base/cics/cobol/XFRFUN.cbl:1014`, `src/base/cics/cobol/XFRFUN.cbl:1091`, `src/base/cics/cobol/XFRFUN.cbl:1384`; arithmetic/outputs: `src/base/cics/cobol/XFRFUN.cbl:986`, `src/base/cics/cobol/XFRFUN.cbl:1033`, `src/base/cics/cobol/XFRFUN.cbl:1357`, `src/base/cics/cobol/XFRFUN.cbl:1554`, `src/base/cics/cobol/XFRFUN.cbl:911`.

- **XFRFUN-R06 - A missing account produces a side-specific failure and explicit rollback, not successful history.** FROM SELECT `SQLCODE=+100` sets `N/1`; TO SELECT `+100` sets `N/2`. The TO routine rolls back itself, and the orchestrator also rolls back the recognized missing-account return; FROM missing-account handling rolls back in the orchestrator. Failure exits bypass history writing. Other failure codes in these orchestrator branches abend `FROM` or `TO  ` instead of following the missing-account return. Example: `COMM-FACCNO=00000001`, `COMM-TACCNO=00000002`, `COMM-AMT=10.00`, FROM update succeeds but TO is absent -> `N/2` and rollback. `COMM-FAVBAL`/`COMM-FACTBAL` may still contain the provisional debit because rollback does not restore COMMAREA fields; they must not be interpreted as committed balances. Evidence: `src/base/cics/cobol/XFRFUN.cbl:406`, `src/base/cics/cobol/XFRFUN.cbl:479`, `src/base/cics/cobol/XFRFUN.cbl:501`, `src/base/cics/cobol/XFRFUN.cbl:617`, `src/base/cics/cobol/XFRFUN.cbl:766`, `src/base/cics/cobol/XFRFUN.cbl:898`, `src/base/cics/cobol/XFRFUN.cbl:967`, `src/base/cics/cobol/XFRFUN.cbl:1033`, `src/base/cics/cobol/XFRFUN.cbl:1102`, `src/base/cics/cobol/XFRFUN.cbl:1111`.

- **XFRFUN-R07 - Other FROM database errors are technical failures, not insufficient-funds rejections.** A nonzero FROM SELECT other than `+100`, or any nonzero FROM UPDATE, sets `COMM-SUCCESS='N'`, `COMM-FAIL-CODE='3'` and exits that routine; the orchestrator's non-`1` paths record and abend `FROM`. There is no FROM-side explicit deadlock retry in these branches. Example: `COMM-AMT=10.00`, FROM UPDATE `SQLCODE=-911` -> internal `N/3`, then `FROM`, not the TO retry rule. Evidence: `src/base/cics/cobol/XFRFUN.cbl:964`, `src/base/cics/cobol/XFRFUN.cbl:967`, `src/base/cics/cobol/XFRFUN.cbl:1014`, `src/base/cics/cobol/XFRFUN.cbl:501`, `src/base/cics/cobol/XFRFUN.cbl:579`, `src/base/cics/cobol/XFRFUN.cbl:617`, `src/base/cics/cobol/XFRFUN.cbl:669`.

- **XFRFUN-R08 - Preserve the unresolved TO-read fall-through; do not describe all read failures as fatal.** For a nonzero TO SELECT other than `+100`, the source sets `N/3`, but the `RUF2` LINK/ABEND is nested under `SQLCODE=-911`. For other SQLCODEs, the sentence ends and reaches balance addition/UPDATE despite the failed read. Example: `COMM-AMT=10.00`, TO SELECT `SQLCODE=-904` -> source assigns `N/3` and then reaches arithmetic/UPDATE; the eventual account state and return are **unresolved**, not a promised rejection or success. Stop interpretation here pending XFRFUN-Q02. Evidence: `src/base/cics/cobol/XFRFUN.cbl:1091`, `src/base/cics/cobol/XFRFUN.cbl:1102`, `src/base/cics/cobol/XFRFUN.cbl:1188`, `src/base/cics/cobol/XFRFUN.cbl:1197`, `src/base/cics/cobol/XFRFUN.cbl:1345`, `src/base/cics/cobol/XFRFUN.cbl:1350`, `src/base/cics/cobol/XFRFUN.cbl:1357`.

- **XFRFUN-R09 - A specific TO-side deadlock requests a bounded restart of account processing.** For TO SELECT or UPDATE `SQLCODE=-911` and `SQLERRD(3)=13172872`, increment a shared counter initialized to zero. Values 1 through 5 request rollback, a one-second delay, then `GO TO UPDATE-ACCOUNT-DB2`; value 6 does not retry and proceeds to fatal handling. Example: `COMM-AMT=10.00`, first matching TO deadlock -> counter `1` and requested restart; sixth matching error -> no delay/restart, SELECT abends `RUF2` or UPDATE abends `RUF3`. This is a source-level restart policy, **not proof of six clean complete attempts**: the jump crosses active PERFORM boundaries (XFRFUN-Q03). Rollback-response failures abend `HROL`. Evidence: `src/base/cics/cobol/XFRFUN.cbl:279`, `src/base/cics/cobol/XFRFUN.cbl:1197`, `src/base/cics/cobol/XFRFUN.cbl:1199`, `src/base/cics/cobol/XFRFUN.cbl:1203`, `src/base/cics/cobol/XFRFUN.cbl:1279`, `src/base/cics/cobol/XFRFUN.cbl:1282`, `src/base/cics/cobol/XFRFUN.cbl:1397`, `src/base/cics/cobol/XFRFUN.cbl:1398`, `src/base/cics/cobol/XFRFUN.cbl:1402`, `src/base/cics/cobol/XFRFUN.cbl:1476`, `src/base/cics/cobol/XFRFUN.cbl:1479`, `src/base/cics/cobol/XFRFUN.cbl:1546`.

- **XFRFUN-R10 - TO fatal-error diagnostics differ between read and update; retain the exact literals.** A TO SELECT `-911` that does not restart ultimately abends `RUF2`; reason `13172894` adds timeout diagnostics. A TO UPDATE nonzero result that does not restart ultimately abends `RUF3`, although its diagnostic record says `RUF2`. Its timeout text tests `13172872`, the same reason used for deadlock, rather than the SELECT path's `13172894`. Example: `COMM-AMT=10.00`, TO UPDATE `-911/13172894` -> no source-coded retry, no matching timeout-message branch, diagnostic code `RUF2`, actual abend `RUF3`. No correction or intended reason mapping is inferred (XFRFUN-Q04). Evidence: `src/base/cics/cobol/XFRFUN.cbl:1288`, `src/base/cics/cobol/XFRFUN.cbl:1322`, `src/base/cics/cobol/XFRFUN.cbl:1329`, `src/base/cics/cobol/XFRFUN.cbl:1345`, `src/base/cics/cobol/XFRFUN.cbl:1384`, `src/base/cics/cobol/XFRFUN.cbl:1485`, `src/base/cics/cobol/XFRFUN.cbl:1522`, `src/base/cics/cobol/XFRFUN.cbl:1529`, `src/base/cics/cobol/XFRFUN.cbl:1546`.

- **XFRFUN-R11 - Normal success requires two transfer-history inserts, one debit and one credit.** After the account-update paths complete, write FROM then TO rows with type `TFR`, eyecatcher `PRTR`, opposite signed amounts, the same task-number reference/date/time, and a `TRANSFER` description containing the other account's sort code and number. A nonzero first INSERT records/abends `WPCD`; a nonzero second INSERT records/abends `WPCT`, so neither is a normal success return. Example: `COMM-FACCNO=00000001`, `COMM-TACCNO=00000002`, `COMM-AMT=12.34`, task `123` -> history amounts `-12.34/+12.34`, reference `000000000123`, descriptions pointing respectively to `987654/00000002` and `987654/00000001`. `COMM-SUCCESS='Y'` follows completion of this section; this is not independent proof of a committed unit of work. Evidence: `src/base/cics/cobol/XFRFUN.cbl:911`, `src/base/cics/cobol/XFRFUN.cbl:1582`, `src/base/cics/cobol/XFRFUN.cbl:1594`, `src/base/cics/cobol/XFRFUN.cbl:1605`, `src/base/cics/cobol/XFRFUN.cbl:1612`, `src/base/cics/cobol/XFRFUN.cbl:1614`, `src/base/cics/cobol/XFRFUN.cbl:1654`, `src/base/cics/cobol/XFRFUN.cbl:1724`, `src/base/cics/cobol/XFRFUN.cbl:1734`, `src/base/cics/cobol/XFRFUN.cbl:1754`, `src/base/cics/cobol/XFRFUN.cbl:1791`, `src/base/cics/cobol/XFRFUN.cbl:1861`; condition literals/layout: `src/base/cics/copy/PROCTRAN.cpy:47`, `src/base/cics/copy/PROCTRAN.cpy:50`.

- **XFRFUN-R12 - The SQL storm-drain check logs a condition; it does not itself reject, retry or roll back a transfer.** It matches positive `SQLCODE=923` to `DB2 Connection lost `, otherwise `Not Storm Drain     `, and displays only for the former. It does not set `WS-STORM-DRAIN` or COMMAREA results. Example: with `COMM-AMT=10.00`, an error path invoking the check at `SQLCODE=923` emits the condition message; at `-923` it takes `WHEN OTHER`. Subsequent behavior belongs to the calling error path, not this check. Evidence: `src/base/cics/cobol/XFRFUN.cbl:1889`, `src/base/cics/cobol/XFRFUN.cbl:1899`.

- **XFRFUN-R13 - The installed abend handler treats AFCR/AFCS/AFCT differently from other abends.** These three codes set `WS-STORM-DRAIN='Y'`, request rollback, and on normal rollback return `COMM-SUCCESS='N'`, `COMM-FAIL-CODE='2'`; failed rollback records/abends `HROL`. `AD2Z` prints SQL diagnostics; the final `WS-STORM-DRAIN='N'` decision reissues the captured code with `NODUMP`. Example: `COMM-AMT=10.00`, captured `AFCR`, successful rollback -> `N/2`, which is not evidence that TO is missing. Whether those VSAM-related abends can reach this DB2 transfer path is unknown (XFRFUN-Q05); do not label the branches dead. This applies only when the handler is entered, not to preceding explicit `ABEND ... CANCEL` paths. Evidence: `src/base/cics/cobol/XFRFUN.cbl:242`, `src/base/cics/cobol/XFRFUN.cbl:272`, `src/base/cics/cobol/XFRFUN.cbl:1931`, `src/base/cics/cobol/XFRFUN.cbl:1952`, `src/base/cics/cobol/XFRFUN.cbl:1966`, `src/base/cics/cobol/XFRFUN.cbl:2034`, `src/base/cics/cobol/XFRFUN.cbl:2042`.

The error-recording LINK above targets `ABNDPROC` through the literal in `WS-ABEND-PGM` (`src/base/cics/cobol/XFRFUN.cbl:257`). It attempts a write to `ABNDFILE` and displays/returns on a write-response failure; an attempted LINK is therefore not a guarantee of a persisted diagnostic (`src/base/cics/cobol/ABNDPROC.cbl:141`, `src/base/cics/cobol/ABNDPROC.cbl:149`). This agrees with the scanned LINK target (`docs/modernization/00-source-of-truth/call-graph.md:365`); the ACCOUNT/PROCTRAN access surfaces agree with `docs/modernization/00-source-of-truth/data-access.md:9` and `docs/modernization/00-source-of-truth/data-access.md:12`.
